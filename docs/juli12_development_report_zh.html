1.3 已批准的設計決策與範圍邊界

  1. 收費規則（Approved Fee Policy）：每開始一小時（per started hour）收費 20 MOP，每個連續 24 小時（1440 分鐘）週期封頂 400 MOP；超過 24 小時後的下一個週期按相同規則累計（例如 24 小時 1 分鐘 = 400 + 20 = 420 MOP）。0 分鐘收費 0 MOP，負時長拒絕。
  2. 角色會話與登出模型（Role Session Model）：採用本地角色選擇會話（1 = ordinary、2 = administrator、0 = exit），每個角色會話內均提供顯式登出（0 = logout）返回頂層菜單，不額外引入未要求的密碼賬號註冊子系統。
  3. 嚴格排除的可選功能：不引入 OpenCV 圖像識別、GUI、網絡服務、外部數據庫、車位容量上限攔截或歷史離場歸檔表，確保核心業務邏輯純粹、可重複驗證。

  1. 車輛記錄結構體（VehicleRecord，定義於 src/vehicle.h:20-26）： cpp struct VehicleRecord { std::string plate; // 車牌號（唯一主鍵，無內部空格） std::string category; // 汽車品類（如 轎車、SUV） std::string color; // 汽車顏色（如 黑色、白色） std::string entry_time_text; // 標準化入場時間文本 (YYYY-MM-DD HH:MM) std::time_t entry_timestamp{}; // 歸一化至本地整分鐘 (tm_sec = 0) 的時間戳 };
  2. 計費結果結構體（ParkingFee，定義於 src/fee_calculator.h:19-26）： cpp struct ParkingFee { std::int64_t total_minutes = 0; // 總停留分鐘數 std::int64_t days = 0; // 完整 24 小時天數 (total_minutes / 1440) int hours = 0; // 剩餘部分小時數 ((total_minutes % 1440) / 60) int minutes = 0; // 剩餘部分分鐘數 (total_minutes % 60) int started_hours_in_partial_block = 0; // 剩餘部分向上取整計費小時數 std::int64_t mop = 0; // 應收澳門元整數金額 (MOP) };

3.1 系統整體運行與角色會話路由流程圖（Overall System Flowchart）

邏輯說明（對應 src/main.cpp、src/menus.cpp、src/ordinary_user.cpp、src/admin_user.cpp）： 1. 程序啟動後首先調用 storage.Load(service) 檢查並載入 parking_data.txt（若主文件缺失但 .bak 存在則自動恢復）。若文件損壞或無法讀取，輸出具體行號/原因並直接返回退出碼 1，絕不覆蓋損壞文件。 2. 載入成功後，打印收費標準說明，進入 RunMenu 頂層角色選擇循環：輸入 1 進入普通用戶會話，輸入 2 進入管理員會話，輸入 0 或遇到 EOF 退出循環。 3. 普通用戶會話僅能執行 1 = list、2 = find、3 = count 與 0 = logout；管理員會話除上述三項外還可執行 4 = add、5 = modify、6 = delete，且每次寫操作成功後立即觸發 storage.Save(service)。 4. 頂層菜單退出時，主函數再次調用 storage.Save(service) 確認落盤並根據保存結果返回退出碼 0 或 1。

3.2 管理員增刪改（CRUD）與即時持久化流程圖（Module Flowchart 1）

邏輯說明（對應 src/admin_user.cpp:58-92 與 src/parking_service.cpp:20-85）： 1. 在管理員會話中選擇 4（添加）、5（修改）或 6（刪除）。若為 5 或 6，首先讀取目標車牌 Existing plate；若為 4 或 5，調用 ReadRecord() 讀取四項字段（Plate、Category、Color、Entry time）。 2. ParkingService 首先在服務層入口強制檢查 role == Role::kAdmin（若非管理員則返回 VehicleResult::kForbidden）。 3. 調用 Validated() 進行三層嚴格校驗： - NormalizeField()：拒絕任何 ASCII 控制字符（< 0x20 或 0x7F），裁剪首尾空格，拒絕空字串，並禁止 plate 內部包含空格。 - ParseTimestamp()：檢查 16 字符 YYYY-MM-DD HH:MM 語法、公曆每月天數（含閏年 2 月 29 日規則）及 std::mktime 往返一致性。 - NormalizeToMinute()：將系統當前參考時間歸一化至整分鐘，若 entry_timestamp > minute 則判定為未來時間並返回 VehicleResult::kFutureTime。 4. 檢查車牌存在性與唯一性：添加時若車牌已存在，或修改車牌名稱時新車牌與其他在場車輛衝突，均返回 kDuplicatePlate，且保持原內存數據不變。 5. 內存更新成功後，立即調用 storage.Save(service)：若保存成功則輸出 Updated and saved. Parking data saved.；若磁盤保存失敗，輸出警告 Updated in memory, but save failed: <reason>，明確告知用戶變更僅在內存生效而未落盤。

3.3 確定性停車時長與費用計算流程圖（Module Flowchart 2）

邏輯說明（對應 src/fee_calculator.cpp:22-45 與 src/parking_service.cpp:99-124）： 1. 批量列表查詢 ListWithFees() 在開始時僅捕獲一次參考時間戳並歸一化至本地整分鐘，確保同一張列表內所有車輛的時長與費用基於完全一致的時間基準。 2. CalculateParkingFee(entry, reference, result) 將入場時間 entry 與參考時間 reference 均通過 NormalizeToMinute() 抹除秒數（設 tm_sec = 0），消除實時秒數引起的跨分鐘/跨小時邊界抖動。 3. 計算秒數差 seconds = std::difftime(end, start)：若 seconds < 0（負時長）、非有限值或超出整數安全上限，立即返回 false 並保持調用方輸出結構體不變。 4. 將總分鐘數 total_minutes = seconds / 60 拆分為： - 完整 24 小時天數：days = total_minutes / 1440（每天固定收費 400 MOP）。 - 剩餘不滿一天分鐘數：remainder = total_minutes % 1440，折算為顯示小時 hours = remainder / 60 與顯示分鐘 minutes = remainder % 60。 - 剩餘部分向上取整計費小時數：started_hours = (remainder + 59) / 60，部分費用 partial = min(400, started_hours * 20)。 - 總費用：mop = days * 400 + partial。

3.4 本地文件載入、備份恢復與安全保存流程圖（Module Flowchart 3）

邏輯說明（對應 src/storage.cpp:29-177）： 1. 啟動載入與 .bak 自動恢復（Storage::Load）： - 默認先將寫入鎖定標誌設為 blocked_ = true。 - 若 parking_data.txt 與 parking_data.txt.bak 均不存在，初始化空車庫並解除鎖定（blocked_ = false），返回 First run: no parking data file.。 - 若主文件存在則解析主文件；若主文件缺失但 .bak 存在，則解析 .bak 並將其重命名恢復為主文件（返回 Recovered parking data from parking_data.txt.bak.）。 - ParseFile() 採用全有或全無（All-or-Nothing）策略：逐行解析 4 列 Tab 分隔字段並校驗時間戳與車牌唯一性；一旦某行格式錯誤或車牌重複，立即中止並返回精確行號（如 Line 3: expected four tab-separated fields.），原 service 保持不變且 blocked_ 維持為 true，防止後續保存覆蓋損壞文件或備份。 2. 多步驟文件保存與回滾協議（Multi-step Save & Rollback Protocol，Storage::Save）： - 若 blocked_ == true，直接拒絕保存（Save blocked: resolve the load or recovery error and reload first.）。 - 先在內存中對待保存的所有記錄做二次完整校驗，隨後寫入臨時文件 parking_data.txt.tmp 並檢查 flush() / close() 流狀態（寫入失敗則刪除 .tmp 並保留原文件）。 - 若目標文件 parking_data.txt 已存在，先調用 ParseFile() 確認磁盤上的當前文件未被外部改壞（若已損壞則設 blocked_ = true、刪除 .tmp 並中止保存），再移除舊 .bak 並將原文件重命名備份為 parking_data.txt.bak；若目標文件不存在但檢測到殘留 .bak（或無法檢查 .bak），則設 blocked_ = true 並拒絕保存（Backup exists or cannot be inspected; reload to recover before saving.）。 - 將 .tmp 重命名為 parking_data.txt：若替換失敗，自動嘗試將 .bak 重命名回滾為 parking_data.txt（若回滾也失敗則保留 .bak 並設 blocked_ = true，輸出 Replacement and rollback failed; preserve backup ...）；若替換成功，清理臨時 .bak（若清理 .bak 失敗則返回 Saved; old backup could not be removed: ...）並返回 Parking data saved.。

第五章 系統局限性與可優化的邏輯及代碼討論

根據作業要求二（3）「討論系統內是否有可優化的邏輯及代碼部分」，本章節在不改動已凍結基線功能的前提下，從算法複雜度、I/O 性能、並發安全與工程擴展四個維度對當前系統進行客觀分析與優化探討：

5.1 現有設計的局限性分析

  1. 每次修改全量重寫與預校驗的 O(N) I/O 開銷： - 在 src/storage.cpp:106-143 中，Storage::Save() 每次保存時會先將內存中的全部記錄拷貝至臨時 ParkingService checked 進行二次校驗，並且當 parking_data.txt 已存在時，會先調用 ParseFile(path_, current) 讀取並校驗磁盤上的舊文件，隨後再將全部記錄寫入 .tmp。 - 局限性：對於酒店停車場日常百輛至千輛規模的在場車輛，全量讀寫耗時僅在毫秒級，且能提供極高的數據防損壞安全性；但若車庫規模擴展至十萬級以上，每次單車增刪改都觸發 O(N log N) 的全量解析與重寫，會產生明顯的磁盤 I/O 放大。
  2. 多步驟文件重命名的非事務性（Non-Atomic Multi-Rename）： - 在標準 C++17 std::filesystem 中，跨平台文件替換需依次執行 rename(target, backup) 與 rename(temp, target) 兩步操作。雖然系統設計了回滾與啟動時自動從 .bak 恢復的閉環機制，但它屬於「可恢復的多步協議（Recoverable Protocol）」，而非操作系統內核級的單步原子事務（如 POSIX 同目錄 rename 覆蓋或 Windows ReplaceFileW / NTFS TxF）。
  3. 單進程獨佔模式與缺乏文件鎖（File Locking）： - 系統假設同一時間僅有一個控制台進程讀寫同一份 parking_data.txt。若多個終端窗口同時啟動並併發修改同一文件，後保存的進程會覆蓋先保存進程的變更。
  4. 本地時區與夏令時（DST）轉換邊界： - 時間解析與分鐘歸一化依賴 C 標準庫 std::localtime 與 std::mktime（tm_isdst = -1）。在澳門（UTC+8，無夏令時）環境下完全精確且單調；但若部署在實行夏令時的地區，每年夏令時回撥的 1 小時重疊窗口內可能出現本地時間文本歧義。

5.2 可優化的代碼與邏輯方向（未來演進建議）

  1. 引入追加式預寫日誌（Append-Only WAL / Journal）與定期壓縮（Compaction）： - 優化方案：管理員執行單次 add、modify、delete 時，僅以 O(1) 時間向日誌文件追加一行增量操作記錄並 flush；僅在程序正常退出或日誌達到閾值時執行一次全量快照合併（Compaction）。這樣既保留了崩潰恢復能力，又將單次寫操作的磁盤 I/O 複雜度從 O(N) 降至 O(1)。
  2. 消除保存路徑上的冗餘內存重構： - 優化方案：由於 ParkingService 的所有公開寫接口（AddVehicle、ModifyVehicle）在寫入 records_ 前已經強制通過了 Validated() 校驗，內存中的 VehicleRecord 始終滿足不變量。因此 Storage::Save() 中的 ParkingService checked 二次插入（src/storage.cpp:106-115）可簡化為輕量級的字段斷言，將保存時的內存分配與紅黑樹插入開銷減少 50%。
  3. 雙索引或哈希索引加速單車查找（std::unordered_map + 有序視圖）： - 優化方案：當前 std::map 查找為 O(log N)。若高頻執行單車牌精確查找（FindByPlate / FindWithFee），可增加 std::unordered_map<std::string, VehicleRecord> 實現 O(1) 平均查找，或僅在需要按車牌有序輸出時對指針數組排序。
  4. 時間類型升級至 C++20 std::chrono::utc_clock / sys_minutes： - 優化方案：若未來升級編譯標準至 C++20，可使用 <chrono> 日曆庫（std::chrono::year_month_day 與 std::chrono::sys_minutes）替代傳統 std::tm / std::mktime，實現無鎖、線程安全且與時區無關的日期算術。

6.1 系統簡介與功能範圍

本系統包含三項必選模塊： 1. 汽車信息模塊（1.1）：支持手動錄入車牌號（Plate）、汽車品類（Category）、汽車顏色（Color）及停車時間點（Entry time，格式 YYYY-MM-DD HH:MM）；支持按車牌號顯示、查找、修改和刪除車輛；支持統計停留時長（X days Y hours Z minutes）與在場車輛總數（Current count）；支持本地文件 parking_data.txt 自動保存與重啟載入。 2. 普通用戶模塊（1.2）：支持顯示所有車輛與費用（1 = list）、按車牌查詢單車與費用（2 = find）、統計在場車輛總數（3 = count）及退出普通用戶登錄（0 = logout）。普通用戶無權執行任何增刪改操作。 3. 管理員用戶模塊（1.3）：具備普通用戶所有查詢統計功能（1–3），並支持添加（4 = add）、修改（5 = modify）、刪除（6 = delete）及退出登錄（0 = logout）。

範圍說明：本系統採用手動輸入車牌號方案，不包含可選的 OpenCV 圖像識別、GUI、外部數據庫、密碼註冊系統、車位上限攔截或歷史離場記錄表。
